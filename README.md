# DocMind — AI-Powered Document Intelligence Platform

DocMind is a full-stack RAG (Retrieval-Augmented Generation) application that lets users upload PDF documents and query them through natural language. The backend handles document ingestion, semantic search, conversation history, and real-time LLM streaming.

---

## Architecture Overview

```
PDF Upload → Supabase Storage (file)
           → PostgreSQL (metadata)
           → pgvector in PostgreSQL (embeddings via HuggingFace API)

Chat       → HuggingFace API (embed question)
           → pgvector cosine search (retrieve relevant chunks)
           → Groq LLM (stream answer)
           → PostgreSQL (save conversation history)
```

## API Reference

### POST `/doc` — Upload Document

Uploads a PDF, parses it, chunks the text, generates embeddings, and stores everything.

**Request:** `multipart/form-data`

| Field | Type | Description |
|---|---|---|
| file | PDF file | The document to upload |

**Response:**
```json
{
  "message": "Document uploaded successfully",
  "document_id": 1,
  "chunks_created": 12,
  "filename": "report.pdf",
  "storage_url": "https://supabase.co/storage/..."
}
```

---

### POST `/chat` — Chat With Document

Takes a user question, retrieves relevant chunks via semantic search, builds a prompt with conversation history, and streams the LLM response.

**Request:** `application/json`

| Field | Type | Description |
|---|---|---|
| question | string | The user's question |
| document_id | integer | ID returned from /doc |
| session_id | string | Unique ID for the conversation session |

```json
{
  "question": "What is this document about?",
  "document_id": 1,
  "session_id": "abc-123"
}
```

**Response:** Streaming plain text (word by word)

## How It Works

### Upload Flow

```
1. PDF received as bytes
2. Uploaded to Supabase Storage
3. Text extracted using PyMuPDF (fitz)
4. Text split into 500-word chunks with 50-word overlap
5. Each chunk embedded via HuggingFace API → 384-dimensional vector
6. Vectors stored in PostgreSQL using pgvector
7. Document metadata saved to PostgreSQL
```

### Chat Flow

```
1. Last 10 messages loaded from conversations table (5 turns of history)
2. User question embedded via HuggingFace API
3. pgvector cosine distance search → top 5 relevant chunks retrieved
4. Prompt built: chunks + conversation history + current question
5. Prompt sent to Groq LLM with streaming enabled
6. Tokens streamed back to frontend word by word
7. Full response + user message saved to conversations table
```

### Conversation History

Every message (user and assistant) is saved to the `conversations` table with a `session_id`. On each new message, the last 10 rows for that session are loaded and injected into the prompt — giving the LLM memory of the conversation.

The `session_id` is generated by the frontend using `crypto.randomUUID()` when a chat session opens and sent with every request.

## Database Schema

### `documents`
| Column | Type | Description |
|---|---|---|
| id | Integer | Primary key |
| filename | String | Original PDF filename |
| storage_url | String | Supabase Storage public URL |
| uploaded_at | DateTime | Upload timestamp |

### `chunks`
| Column | Type | Description |
|---|---|---|
| id | Integer | Primary key |
| document_id | Integer | Foreign key → documents.id |
| content | Text | 500-word chunk of PDF text |
| embedding | Vector(384) | pgvector embedding |

### `conversations`
| Column | Type | Description |
|---|---|---|
| id | Integer | Primary key |
| session_id | String | Groups messages by conversation |
| document_id | Integer | Which document this conversation is about |
| role | String | "user" or "assistant" |
| content | Text | Message content |
| created_at | DateTime | Message timestamp |

## Local Setup

```bash
# Clone the repo
git clone https://github.com/Koushik140803/DocMind-backend.git
cd DocMind-backend

# Create virtual environment
python -m venv venv
source venv/bin/activate        # Mac/Linux
venv\Scripts\activate           # Windows

# Install dependencies
pip install -r req.txt

# Add your .env file with the keys above

# Run the server
uvicorn engine.main:app --reload --port 5000
```

Open `http://localhost:5000/docs` for the interactive API UI.

## Prerequisites

- Python 3.11
- PostgreSQL with pgvector extension enabled
- Supabase project with a `documents` storage bucket
- HuggingFace API key (free at huggingface.co)
- Groq API key (free at console.groq.com)

Enable pgvector in your PostgreSQL database:
```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

## Key Design Decisions

**Why pgvector instead of ChromaDB?** pgvector stores vectors directly in PostgreSQL — no separate vector database needed. Everything lives in one place, survives restarts, and is free on Supabase.

**Why HuggingFace for embeddings?** Free API, no local memory usage (critical for Render's 512MB free tier limit), and `all-MiniLM-L6-v2` is a well-proven model for semantic search.

**Why separate `/doc` and `/chat` endpoints?** Clean separation of concerns — upload and search are independent operations. Easier to debug, test, and extend.

**Why session-based history?** Stateless backend — no WebSocket complexity. Frontend generates a UUID per session and sends it with every message. Backend loads history from PostgreSQL on each request.
